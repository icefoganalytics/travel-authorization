# API Service

The API service is the backend for Travel Authorization.

If you are new to the project, read the root [README.md](../README.md) first, then come back here
for backend-specific details.

It is responsible for:

- authentication and authorization
- travel authorization and Travel Desk business logic
- database access and migrations
- integrations and scheduled jobs
- serializer and policy-backed API responses

## How It Is Used

In normal development, the API service is usually run through the `dev` wrapper.

To run only the API service:

```bash
dev up api
```

To run the full app stack instead:

```bash
dev up
```

The API is available through the gateway at `http://api.<gateway-hostname>` (without a port
binding). Replace `<gateway-hostname>` with the checkout-derived hostname shown by Vite at startup;
if `GATEWAY_HOSTNAME` is set, use that value. The matching browser origin is
`http://<gateway-hostname>`. Log in through that browser origin before inspecting API responses.

## Report Downloads

Travel Desk PDF and CSV reports are generated by the API, not the browser. The browser submits an authenticated form to a download URL with the usual `where`, `filters`, and `order` query options; row selection uses `where[id]`. The server applies the same policy scope as the request list and exports all matching authorized requests without list pagination. A query with no visible matches returns not found.

Both formats use `Export, Travel Desk Requests, YYYY-MM-DD` filenames with the appropriate `.csv` or `.pdf` extension.

Query arrays support up to 1,000 entries, with at most 1,500 query parameters overall. Oversized queries are rejected instead of silently changing the selection.

Controllers pass policy-scoped models and query options to the export services. Shared report loading owns the required associations and serialization; exports do not run the list's total-count query.

The reusable Puppeteer renderer lives in [`src/lib/generate-pdf.ts`](src/lib/generate-pdf.ts) and owns the browser lifecycle without Travel Desk dependencies. The report service owns PDF options, escaped local templates, and the embedded logo. CSV generation uses `fast-csv`, a UTF-8 byte-order mark, and spreadsheet-formula neutralization.

Both development and production images provide system Chromium through `PUPPETEER_EXECUTABLE_PATH` and disable Puppeteer's bundled browser download. The production build copies `src/templates` into `dist/templates`. Keep Chromium and Puppeteer compatible, and exercise an actual generated PDF when changing either dependency or image.
